SpotNav for Home Assistant 1.17.1 keeps every current written to a charger within the main fuse, keeps the app's webhook ids out of view, makes SpotNav's services administrators' only, and runs the OCPP pilot-floor probe only when asked.

## Load balancing

- **Every current write respects the fuse.** A few writes did not go through load balancing: the current sent again after an Easee status blip or a plug-in, the write deferred until a charge has started, and solar's own write. They could put the full requested current on a charger, and load balancing did not learn of it, so the next overload could read as "no change" and the charger stayed above what the main fuse allows. Now each such write is held to the site's allowance (never below the charger's minimum) and recorded with load balancing. As a second safeguard, an overload is lowered from the current the charger actually reports, when that reading is newer than the last write.

## Security

- **No webhook ids in entities.** The *App connection* and *App pairing* sensors carried the app's webhook ids, the webhook URL and a pairing link in their attributes, where every user and the recorder could see them. A webhook id is the only key to its charger's webhook. The two sensors are removed, and on upgrade their entities and their recorded history are deleted. The app gets its webhook only through pairing, which an administrator approves in Home Assistant.
- **Services are for administrators.** `dismiss_vehicle`, `undismiss_vehicle`, `unconfirm_vehicle`, `confirm_charge_limit`, `unconfirm_charge_limit`, `confirm_vehicle_soc` and `send_test_notification` now refuse a user who is not an administrator, as the card's commands for the same decisions do. Automations keep working.

## OCPP

- **The pilot-floor probe runs only when asked.** Once per installation, during a planned charge, SpotNav tried 5, 3 and 1 A on an OCPP charger that sets its current through `AssignedCurrent`, to learn how low the charger goes. It no longer runs by itself. An administrator can run it as a diagnostic (see *The pilot-floor probe* in docs/ocpp.md). A run interrupted by a restart is put back automatically when SpotNav starts.

## Reliability

- **No blocking time-zone lookups.** The price areas' time zones are now looked up when price data is fetched or restored, outside Home Assistant's event loop, instead of the first time a plan or the card needed them.

SpotNav for Home Assistant 1.14.4 stops the site sensors from filling the recorder database.

## Recorder database

- **The site sensors are written only when they change.** The site's *Capacity state* sensor was written with every meter reading, on some sites twice a second, and carried 41 attributes, among them the age of each phase's reading. Every write was a new row in the recorder, and on one install it took several gigabytes in ten days. It is now written only when its state or one of its attributes really changes, which is a few times an hour on a quiet site. The *Proposed current* sensor of each charger follows the same rule.
- **Fewer attributes.** *Capacity state* keeps what a person reads it for: the reason, the site's activity, the confidence, the measurement mode, whether active load balancing is available and on, and whether solar is available. The per-phase readings and their ages, the headroom figures, the limiting phase and the per-charger solar, hybrid and load-balancing detail are gone from the attributes and are in the debug file (Settings → Support → Download debug info), which now also has the solar, hybrid and yield-stepping state of each charger. *Proposed current* no longer carries the charger's measured current per phase or the limiting phases, and its currents are rounded to 0.1 A. Templates or automations that read a removed attribute, such as `grid_power`, `limiting_phase` or a solar `start_a`, get nothing now; `docs/api.md` says where each one went.
- **Diagnostic attributes stay out of the history.** The attributes that only describe the setup are no longer stored in the recorder.

If you excluded *Capacity state* from the recorder, you can remove the exclusion. The old rows age out with the recorder's `purge_keep_days` (10 days by default); to get the space back at once, run `recorder.purge` with `repack: true`.
